1 · The environment

A team runs an AI agent on Kubernetes.

The agent takes tasks, calls a model outside the cluster, and uses tools named in its MCP config. One of its tools runs code it is given. Nothing limits what the pod can reach.

2 · Collect

Read what is already written, watch what really happens.

No new agent in the cluster. The product reads the configuration the team already wrote, and uses the engines already running - Cilium's Hubble and Tetragon - to watch.

3 · Profile

One profile, four layers.

Every row crosses three questions: is it needed (from the configuration), was it seen (from watching), and what is allowed today. Point at a row for its evidence.

Open - neededAsk - needed, not seen yetSuspect - seen, nothing needs itClose - nothing needs it
4 · Decide

Seen is not trusted. Needed is never closed.

Two examples from this agent's profile.

5 · Prove and enforce

Every stage proven three times before it goes live.

Rehearsal on the cards, replay on real recordings, then Watching on the cluster in log-only mode - Cilium audit mode and Tetragon monitor - before anything is enforced. A person approves each stage.

6 · The attack

The same attack, before and after.

An attacker poisons a task in the queue. The agent does what agents do: it runs the code through its own run_code tool. That code tries five things.
